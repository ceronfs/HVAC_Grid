# HVAC Grid 통합 UI 목업 — 디자인 리뷰

- 작성: 2026-10-18 · 관점: CAD/엔지니어링 데스크톱 도구 UI 설계 (정보 구조, 시각 위계, 접근성, 한국어 타이포)
- 대상: `docs/ui/mockup.template.html`, 목업 화면 `mockup-1`~`mockup-8`
- 비교 기준: BOX CAL Enhance 현행(`box-1`~`box-5`), PHG D 현행(`phg-1`~`phg-3`), `ui-report.json`
- 대비 값은 WCAG 2.x 공식으로 직접 계산했습니다. 다크 모드는 소스 코드를 기준으로 판단했습니다(스크린샷 없음).

---

## 1. 총평

두 도구를 "격실" 데이터 하나로 묶고, ①~⑤ 단계로 작업 흐름을 드러낸 방향은 옳습니다. 두 앱이 같은 토큰을 쓰기 때문에 합쳤을 때 시각적 이질감도 거의 없습니다.
다만 지금 목업은 "가운데 캔버스는 그대로 두고 리본만 단계별로 바꾼" 수준에 머물러 있습니다. 각 단계의 실제 작업 공간이 설계되지 않았고(2단계 부하 표, 5단계 검토 결과), CAD 기본기도 빠졌습니다(실행 취소, 좌표, 스냅, 레이어).
4·5단계 도면에서는 RU 기호가 실 번호를 덮어 판독이 안 되고, 빨강이 선택·부하·Root·오류의 네 가지 뜻으로 섞여 쓰입니다.
BOX / PHG D / 신규 / 설계 데이터 v0 같은 개발자 시점의 표기가 사용자 화면에 그대로 노출된 점도 정리해야 합니다.

| 항목 | 등급 | 한 줄 근거 |
|---|---|---|
| 컨셉 (정보 구조·흐름) | **B+** | 단계 + 트리 + 인스펙터라는 골격은 좋음. 2·5단계의 작업 공간과 단계 상태(완료/재계산)가 빠짐 |
| 시각 완성도 | **C+** | 토큰 일관성은 좋음. 라벨 충돌, 색 의미 혼용, 8 px 태그, 점선 자리표시가 완성도를 깎음 |

## 2. 잘된 점

- **단계별 리본**: 49개 코드 버튼이 두 줄로 늘어선 바(`box-1`)를 단계마다 7~25개로 나눈 것만으로도 인지 부하가 크게 줄었습니다(`mockup-1`, `mockup-3`).
- **공통 토큰 재사용**: #f5f4ef / #fff / #185fa5를 그대로 쓰고, PHG D의 리본 문법(아이콘 + 한국어 라벨 + 그룹 캡션)을 따랐습니다. 두 앱 사용자 모두 낯설지 않습니다.
- **Deck → 격실 트리**: 검색과 필터가 있고, 트리·캔버스·인스펙터 선택이 서로 연동됩니다(`mockup-6`, `mockup-7`). 통합 앱의 중심축으로 적합합니다.
- **인스펙터 카드**: 출처가 다른 결과(부하·풍량·계통·덕트)를 한 실 기준으로 모았습니다. 핵심 값은 20 px로 크게(333 W), 숫자는 `tabular-nums`로 정렬되어 위계가 분명합니다.
- **2단계 히트맵**: 별도의 전체 화면 창(`box-4`) 대신 도면 위에서 부하 분포를 보여 주는 발상이 좋습니다.
- **정직한 데이터 표시**: 가정값은 "임시 (복도 끝)", 덕트 진행도는 "덕트망 2/10 (데모)"처럼 그대로 드러냅니다.
- **3단계(풍량·계통) 명시**: 두 앱 사이에서 엑셀과 수작업으로 메우던 단계를 화면에 올렸습니다.
- **단순한 셸 구조**: CSS grid(44/74/1fr/24 px) 구조라 이후 단계에서 다듬기 쉽습니다.

## 4. 두 원본 앱과의 일관성

### BOX CAL Enhance에서 지킬 것
- **2글자 코드를 명령 별칭으로 남깁니다.** 명령 검색(Ctrl+K, 또는 캔버스에서 바로 입력하는 AutoCAD 명령행 방식)에서 `OA`, `LR`, `RN`, `K7`을 치면 해당 명령이 실행되게 합니다. 툴팁 둘째 줄에도 "이전 단축: OA"를 적습니다. 최소 한 프로젝트 주기 동안 유지합니다.
- **그리기 팔레트는 캔버스 가까이 둡니다.** 1단계에서는 캔버스 왼쪽 가장자리에 28 px 세로 미니 툴바(선·폴리선·사각형·문자·이동·자르기·삭제)를 둡니다. 리본에만 두면 마우스 이동 거리가 늘어납니다(`box-1`의 TX·MV·TR·EX 팔레트에 익숙한 사용자 기준).
- **Deck별 레이어와 Deck 적층 편집**(Z, H, OL 상태; `box-2`): 레이어 탭과 Deck 인스펙터 카드로 옮깁니다(문제 13).
- **3D 보기 프리셋**(ISO, T/D/R/L/F/B, Solid, CK3; `box-3`): 목업의 3D 버튼은 1단계에만 있고 프리셋이 없습니다. 3D 모드에서는 플로팅 바에 프리셋을 펼칩니다.
- **무결성 카운트**("격실 94개 · 계산 완료", "ROOM 21/21 · HULL 0"; `box-2` 하단): 1단계 인스펙터의 Deck 카드와 상태 표시줄에 남깁니다.
- **전체 화면 표 작업**: 숙련자의 CAL 작업 방식은 `표 최대화`로 보존합니다(문제 2).

### PHG D에서 지킬 것
- 아이콘 + 한국어 라벨 + 그룹 캡션 리본 문법, 따뜻한 스타일(`phg-3`). 이미 반영되어 있으니 유지합니다.

### 1단계(iframe 호스팅)에서 UI 측면 주의점
- 포커스가 iframe 안에 있으면 셸 단축키(Ctrl+1~5, Ctrl+Z)가 동작하지 않습니다. 주입 JS에서 keydown을 셸로 전달하고, 실행 취소는 활성 iframe에 위임하며 툴팁에 범위를 표시합니다("BOX 편집 기록").
- 원본 바를 숨길 때 레이어, Deck 적층, 검증 결과 같은 **기능 패널까지 숨기지 않도록** 숨김 대상 목록을 문제 11의 대응표로 관리합니다.
- 트리 ↔ iframe 캔버스 선택 동기화가 늦어지면 인스펙터 머리에 "동기화 중…"을 표시합니다. 조용히 틀린 값을 보여 주는 것보다 낫습니다.

## 5. 우선 반영 목록 (다음 목업 반복)

1. **캔버스 라벨**: 실 번호와 값을 폴리곤 좌상단(8 px 안쪽)에 고정하고 `paint-order:stroke` 3 px 후광을 줍니다. 화면 폭 64/40 px 기준으로 라벨 세부를 줄이고, RU와 Root는 화면 고정 크기 기호로 그립니다.
2. **색 의미 정리**: 선택은 흰 3 px 후광 + #185fa5 2 px, 히트맵은 #fbf1e2 → #e08a3c 5단계에 W 구간 범례, 계통 팔레트는 빨강·초록을 뺀 10색으로 바꿉니다. 빨강은 오류 전용입니다.
3. **출처 표기 정리**: 출처 태그(BOX / PHG D / 신규 / 설계 데이터 v0)와 점선 테두리를 없애고, 툴팁을 "한국어 이름 · 이전 단축: OA · 설명" 형식으로 통일합니다. 남은 코드 라벨(R, ML, BR, SBR, AD, OL)은 한국어로 바꿉니다.
4. **스테퍼 → 탭**: 리본 바로 위 왼쪽 정렬 탭으로 옮기고, 단계별 상태 배지(✓ / 경고 n / ↻), Ctrl+1~5, `role="tablist"`를 적용합니다.
5. **CAD 기본기**: 앱 바에 ↶ ↷를, 상태 표시줄 오른쪽에 좌표(mm)·줌 %·스냅/직교/그리드/그립 토글·자동 저장 시각을 추가합니다.
6. **하단 도크 패널**: 2단계는 BOX CAL 표 탭(설계 조건·경계 조건·K값·격실 부하·신기·리히터), 5단계는 문제 목록 + 캔버스 번호 마커를 넣습니다.
7. **토큰 정비**: `--muted:#595852`, `--warn:#8f5600`, `word-break:keep-all`, 한글 최소 11 px, `:focus-visible`을 적용하고, 캔버스 색을 토큰화한 뒤 웜 다크 테마를 만듭니다.

## 6. 다음 단계 제안 — 선박 HVAC 엔지니어 사용성 테스트

- **과업 기반 비교 테스트(5~6명)**: BOX 숙련자 2명, PHG D 숙련자 2명, 신규 사용자 1~2명. 과제는 "5DK 부하 계산 → 계통 2개 배정 → AUTO 덕트 → 압력 검토 → XLSX 출력"입니다. 완료 시간, 오류 수, 도움 요청 횟수를 현행 두 앱 조합과 같은 사람 안에서 비교합니다.
