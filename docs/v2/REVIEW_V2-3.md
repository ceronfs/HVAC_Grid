같은 답이 나오는 까닭: 규칙·문구·표를 1.0와 같게 명세로 삼았고, 기하 계산의 부동소수 순서까지 맞췄다(S5에서 면적 합 순서가 달라 반올림 0.5 mm가 100 mm 갈린 것을 찾아 고침).

**1.0와 다르게 한 것(같은 기능, 기록):**
- 덕트망을 2.0 덕트 엔진이 만들면 이름이 엔진 것(`G001-D-1`, 1.0 PHG D는 `M-D-1`)이고, 보고서 "가정·근거"의 덕트망 문구와 계통 상태("AUTO 결과 대기")가 엔진에 맞게 바뀐다. 1.0 파일에서 가져온 덕트망이면 1.0 문구 그대로다.
- 1.0는 PHG D 프로젝트 글과 BOX 도면을 프로젝트에 담았다. 2.0 모델은 담지 않는다(D2·D17, 원본은 이름·해시만). T3 모델 파일 615 KB(1.0 프로젝트 1.3 MB).
- 2.0 화면은 편집마다 풍량·계획·검토를 바로 다시 계산하고, 덕트망은 AUTO를 누를 때 바뀐 계획만 다시 만든다(1.0는 계통마다 PHG D로 보냄).

## 4. 강제 항목

| 항목 | 판정 | 근거 |
|---|---|---|
| F-1 풍량은 여름 하나, 겨울은 난방 용량 | **지킴** | 풍량 엔진 `lib/engines/airflow/airflow.cjs room()`은 냉방 현열 × 안전율 × 3 ÷ ΔT와 최소 신기만 씀. 모델 규칙에 겨울 키가 없고(`RULES`), 옛 `heatingSupplyDeltaTK`는 읽을 때 버림·`validate`가 거부. 화면 ③은 ΔT 하나(3~15 K)만 받고 알 수 없는 규칙 키를 거부. 22 K 초과는 `HEATING_DT` "풍량은 그대로, 보조 난방·재열기" 확인. 시험: `engines.test` "one airflow all year"(난방 부하 10배에도 풍량 그대로), `modules.test` F-1, `model.test` F-1. 1.0 시험(`iso7547` "one airflow all year", `contract.test`)도 그대로 통과. BOX CAL 자체 시험은 vendor를 바꾸지 않아 돌리지 않음 |
| F-2 표준 값은 원문으로 | **지킴(원문 미확인 표시)** | 이 환경에 ISO 7547:2022·SOLAS·ASHRAE 원문이 없다. 2.0 엔진의 표준 값(ISO 7547 6.3 15·22 K, 6.4.1 배기, 6.5, 부속서 E; SOLAS II-2 표·조항; 수직 덕트 K값)은 1.0 값 그대로이고 파일 머리에 "원문 미확인"을 적었다(`review/air.cjs`, `fire/*.cjs`, `systems/risers.cjs`, `systems/plans.cjs`). 원문 대조는 K6 전(D18) |
