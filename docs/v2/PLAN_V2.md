# HVAC Grid Ver 2.0 기획서 — HVAC Grid 중심 통합

작성 2026-10-25 · 상태: 기획 — 검토 완료, D1~D6 결정(2026-10-25, [DECISIONS.md](DECISIONS.md)) · 착수는 지시 뒤 · 이전 계획: [PLAN.md](../PLAN.md)(1.0, 2026-10-18 "A 셸 + 브리지 → B 공통 모델 단일 앱") · 첫 단계 세부: [PLAN_PHG_LIB.md](PLAN_PHG_LIB.md)

## 1. 한 줄 요약

받은 일반배치도에서 덕트 도면·방화 등급·보고서까지, **HVAC Grid 한 프로그램 · 한 모델 · 한 캔버스**로 끝낸다. 모든 과정(도면 정리 → 데크·격실 → 부하 → 풍량·계통 → RU·덕트 → 검토·출력)은 **같은 캔버스에 끼우는 모듈**로 진행한다. 단계를 바꾸면 화면이 바뀌는 것이 아니라, 캔버스는 그대로이고 그 단계 모듈의 도구·그림 층·패널이 켜진다. 도면 정리(SketchCAD), 부하(BOX CAL), 덕트(PHG D)는 화면째 띄우지 않고 모듈 안의 **엔진**으로 쓴다.

## 4. 원칙

1. **HVAC Grid가 중심이다.** 화면·모델·흐름·저장 파일은 HVAC Grid 것이다. 바깥 프로그램은 엔진(계산)이나 선택 편집기로만 들어온다.
2. **모델은 하나.** 모든 단계가 같은 선박 모델을 읽고 쓴다. 결과에는 입력 해시를 붙여, 입력이 바뀐 것만 다시 계산하고 그것만 "다시 계산 필요"로 보인다(1.0의 `planSig`를 모든 결과로 넓힘).
3. **엔진은 순수 함수.** 입력 = 모델의 일부, 출력 = 결과. 브라우저에서는 Web Worker, 노드에서는 직접 호출.
4. **원본 로직은 다시 짜지 않고 잘라 온다.** 원본 저장소(SketchCAD, PHG, CAL_Enhance)는 그대로 두고, 잘라 내는 도구(`npm run extract:*`)로 `lib/engines/`에 사본을 만든다. 사본 머리에 원본 해시, 단위 시험이 해시 확인. 손으로 쓰는 것은 사본을 모델에 잇는 접착 코드뿐. 원본이 바뀌면 다시 잘라 온다.
5. **원본 단독판은 계속 산다.** SketchCAD.html, PHG D, BOX CAL은 각자 저장소에서 따로 빌드되어 단독으로도 쓴다. 2.0은 그 원본을 갈라 고치지 않는다.
6. **같은 답.** 엔진을 옮길 때 표준 해석·계산 기준을 바꾸지 않는다. 강제 항목 그대로: **F-1** 풍량은 여름(냉방) 기준 하나, 겨울은 같은 풍량에 난방 용량 · **F-2** 표준 값은 원문(ISO 7547:2022 `7547.pdf`)으로 확인하고 조항 번호를 값 옆에. 옮기기 전 결과를 기준값으로 남기고, 옮긴 뒤 같은지 시험한다.
7. **좌표 방향은 하나.** 화면·편집기·출력 파일이 모두 원본 도면(CAD)과 같은 방향으로 보인다. 모델은 BOX처럼 화면 아래쪽이 +y(CAD y의 반대)로 두고, DXF·다른 프로그램과 주고받는 곳(`lib/io`)에서만 뒤집는다. 1.0에서 PHG D 편집기가 ①~④와 위아래 반대로 보였던 문제(2026-10-25 수정)가 다시 생기지 않게 시험으로 지킨다.
8. **단계마다 동작하는 프로그램.** 한 번에 갈아엎지 않는다. 각 단계가 끝나도 프로그램은 1.0처럼 쓸 수 있다.

### 5.1 한 캔버스와 모듈

화면은 **캔버스 하나 + 모듈 여섯**이다. 캔버스는 보기·그리기·고르기만 하고 설계 내용을 모른다. 설계 내용은 모두 모듈이 가져온다.

```
┌ 리본: 지금 단계 모듈의 명령 ──────────────────────────────────────────────┐
├ 트리(데크·격실·계통) │            캔버스 (하나)               │ 속성 패널 │
│  ← 모듈이 채움       │  보기: 이동·확대(공유) · 데크 필터       │ ← 모듈이  │
│                      │  층: 격자·원점축 │ 도면 │ 격실 │ 부하   │   채움    │
│                      │      │ 풍량·계통 │ RU·덕트 │ 방화 │ 글자 │           │
│                      │      │ 선택·손잡이 (위로 갈수록 앞)       │           │
└ 상태줄: 다음 할 일 · 모듈 검사 결과 ───────────────────────────────────────┘
```

**캔버스 코어**(`app/canvas/`, 모듈과 무관)
- 보기: 세계 좌표 mm 하나, 이동·휠 확대·맞춤 — 모든 모듈이 같은 보기를 쓴다(1.0의 BOX 보기 ↔ 셸 SVG 축척 맞춤이 없어짐).
- 층(layer) 쌓기: 각 층은 모듈이 등록, 켜기·끄기·흐리게. 큰 도면 선은 Canvas2D(래스터, SketchCAD 방식), 고를 수 있는 것(격실·RU·덕트)은 위 층에 벡터.
- 데크 필터: 지금 데크만 / 위·아래 데크 흐리게 / 모두 — 상하 관계를 눈으로 확인.
- 고르기(hit test)·스냅·끌기·손잡이·선택 집합: 무엇을 골랐는지만 모듈에 알림.
- 명령 실행기: 모듈이 낸 명령을 모델에 적용하고 실행 취소 하나에 기록.

**모듈**(`app/modules/<id>/` 화면 부분 + `lib/engines/<id>` 계산 부분)

| 단계 | 모듈 | 캔버스 층 | 도구(캔버스에서) | 패널 | 엔진 |
|---|---|---|---|---|---|
| 0 | `drawing` 도면 | 원본 선(정리 전/후), STR·PNL·DECK 색 | 계산용 정리, 경계 지정, **데크로 지정**(영역 + 기준점) | 레이어·용도 규칙, 데크 표(z·층고·기준점) | geometry(SketchCAD 코어) |
| ① | `rooms` 데크·격실 | 격실 외곽·번호·이름, 상하 접촉 | 실 자동 찾기, 실 지정·나누기, 번호 | 격실 표·면적표, 상하 검사 | geometry |
| ② | `load` 부하 | 격실 부하 색(W/m²), 외기 면 표시 | 격실 조건 바꾸기(여러 실) | 설계 조건, K 표, 격실 부하표 | load(CAL 계산부) |
| ③ | `airflow` 풍량·계통 | 계통 색, 풍량 글자, 전달 공기 화살표 | 계통 배정, 공조기 위치, 전달 공기 출처 | 풍량 규칙(F-1), 계통 요약 | airflow · systems |
| ④ | `ducts` RU·덕트 | RU, 덕트(크기 글자), 공조기·수직 덕트 | AUTO, 다른 경로, RU 끌기, 수동 크기 | 계통 결과(Pa·길이), 덕트 속성 | route · size(PHG 엔진) |
| ⑤ | `review` 검토·출력 | 방화 경계 등급, 관통부, 문제 위치 표시 | 문제 항목 → 그 자리로 이동 | 검토표, 출력 | fire · output |

**모듈 약속**(모든 모듈이 같은 모양)

```js
export default {
  id: 'ducts', step: 4, title: 'RU·덕트',
  reads:  ['decks', 'rooms', 'airflow', 'systems', 'plans'],   // 모델에서 읽는 곳
  writes: ['plans', 'networks', 'risers'],                      // 모델에 쓰는 곳 (명령으로만)
  engine: { run(input) {...} },          // lib/engines/* — 순수 함수, 브라우저에선 Worker
  layers: [{ id: 'duct', z: 50, draw(g, model, view) {...}, hit(pt) {...} }],
  tools:  [{ id: 'auto', ribbon: 'AUTO', run(model, sel) => command }, { id: 'ruDrag', onDrag(...) => command }],
  panels: { tree(model), inspector(model, sel), table(model) },
  checks(model) => issues,               // 상태줄·⑤ 검토로 모임
}
```

- **모듈은 모듈을 부르지 않는다.** 서로 모델로만 이어진다(`reads`·`writes`). 예: `ducts`는 `airflow`가 쓴 풍량을 읽을 뿐, `airflow` 함수를 부르지 않는다.
- **다시 계산 표가 순서를 정한다.** 모델의 어느 곳이 바뀌면 그곳을 `reads`하는 모듈의 결과만 "다시 계산 필요"가 된다(격실 조건 → 부하 → 풍량 → 그 계통 덕트).
- **단계를 바꿔도 캔버스는 그대로.** 바뀌는 것은 켜지는 도구·리본·패널과 층의 강조뿐이다. ④에서 방화 층을 켜 덕트와 경계를 겹쳐 보는 식으로, 다른 모듈의 층을 언제든 켤 수 있다.
- **엔진만 따로도 쓴다.** `lib/engines/*`는 화면 없이 노드에서 돈다 — 단위 시험, `tools/hvac-run.cjs`(브라우저 없는 일괄 실행).
- **모듈을 더할 수 있다.** 같은 약속이면 새 모듈(예: 소음, 배관, 3D 보기)을 캔버스·모델을 건드리지 않고 끼운다.

### 5.2 기능의 출처와 2.0의 자리

| 기능 | 1.0에서 | 2.0에서 | 방식 |
|---|---|---|---|
| 큰 DXF 열기·계산용 정리 | SketchCAD(따로) | 단계 0, `engines/geometry` | SketchCAD 코어 잘라 옴 |
| STR·PNL·DECK 경계, 실 찾기, 면적표 | SketchCAD(따로) + BOX 다시 인식 | 단계 0~①, `engines/geometry` | 같음. BOX 격실 인식은 주 경로에서 빠짐 |

## 6. 모델 (schema `hvac-grid/2`, 초안)

```
HVACGridProject v2 {
  schema: 'hvac-grid/2', units: 'mm', created, app: { version: '2.0.x' },
  source:   { files: [{ name, sha256, layersKept }], mapping: <조선소 레이어 규칙> },   // 원본 DXF는 담지 않음
  decks:    [{ id, name, z, height, origin: { x, y }, rotation, order }],              // 상위 레이어
  geometry: { [deckId]: { lines: [{ id, a, b, purpose: 'STR'|'PNL'|'DECK'|'HULL'|'OPENING', layer }],
                          texts: [...] } },                                           // 계산용 정리 결과만
  rooms:    [{ id, deckId, no, name, polygon, holes, areaM2, volumeM3, isoClass }],
  boundaries: [{ id, kind: 'bulkhead'|'deck'|'outer'|'floor'|'ceiling', roomA, roomB?, deckIds,
                 purpose, lengthMm, areaM2, a, b }],                                  // 상하 접촉 포함
  conditions: { project: <설계 조건>, rooms: { [roomId]: <격실 조건> }, k: <K 표·모드> },
  loads:    { [roomId]: { coolingSensibleW, coolingLatentW, coolingW, heatingW, minFreshAirCmh, ... } },
  rules:    { supplyDeltaTK, margin, ... },                                            // F-1: 겨울 풍량 규칙 없음
  airflow:  { [roomId]: { supplyCmh, exhaustCmh, returnCmh, transferFrom, transferInCmh, makeupCmh, basis } },
  systems:  [{ id, kind, unitDeckId, decks, designCmh, fanCmh }],
  plans:    { [deck__system]: { root, rus, avoid, outside } },
  networks: { [deck__system]: { ducts: [{ id, name, type, shape, size, flowCmh, points, manual? }],
                                nodes, pressure: { indexPa, paths } } },
  risers:   [...], solas: { settings, rooms, boundaries, penetrations },
  results:  { [key]: { inputHash, at, ... } },                                         // 다시 계산 표
  history:  <선택: 실행 취소 기록은 저장하지 않음>
}
```

- **격실 id는 형상에서 한 번 정한다.** 단계 0(실 찾기)이 정한 id를 끝까지 쓴다(1.0의 BOX room id ↔ PHG D 대조가 없어짐).
- **원본 DXF는 담지 않는다.** 계산용 정리 결과(경계 선·실 문자)만 담고, 원본은 파일 이름·해시로 기록한다(1.0 BOX 프로젝트는 원본 DXF를 담아 무거워짐 — BIG_DXF 검토).
- **1.0 프로젝트 가져오기.** `lib/io`가 1.0 파일(계약 + PHG D 프로젝트 + BOX JSON)을 v2로 바꾼다. 옛 `rules.heatingSupplyDeltaTK`는 읽을 때 버린다(F-1).
