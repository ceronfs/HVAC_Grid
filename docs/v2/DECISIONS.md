## K0 — 기획서 검토 (2026-10-25)

사용자: 기획서([PLAN_V2.md](PLAN_V2.md)) 확인, D1~D6 **권장안으로 결정**.

| # | 질문 | 결정 | 이 결정이 정하는 것 | 단계 |
|---|---|---|---|---|
| D1 | PHG D 편집기를 남길까 | **남긴다.** 덕트 경로·이음쇠 세부 편집이 필요할 때만 PHG D를 띄우고, 모델 ↔ PHG D 프로젝트로 주고받는다 | V2-1에서 ④ 계산은 엔진, 편집기는 선택. 모델의 덕트망 → PHG D 프로젝트 변환(`serializeTypedProject` 형식)과 되읽기가 필요(PLAN_PHG_LIB 4장 1·2) | V2-1, V2-3 |
| D2 | BOX를 2.0에 남길까 | **주 경로에서 뺀다.** 1.x 프로젝트 열기는 `lib/io/v1.cjs`로. 3D 보기가 필요하면 선택 편집기로 | V2-5 뒤 ①②는 SketchCAD 코어. 한 파일판에 BOX 화면 코드를 기본으로 넣지 않음 | V2-5, V2-6 |
| D3 | SketchCAD 데크 지정을 단독판에도 넣을까 | **넣는다.** 같은 원본(ceronfs/SketchCAD)에서 단독판과 HVAC Grid가 함께 쓴다 | V2-2는 SketchCAD 저장소 작업, 단독판 회귀 시험 포함 | V2-2 |
| D4 | 데크 층고의 정의 | **BOX 정의를 따른다:** 아래 데크 z + 층고 = 위 데크 z(허용 오차 `DECK_STACK_TOL` 안) | SketchCAD 데크 표의 층고 뜻, 상하 접촉(바닥·천장·외기) 판정 | V2-2, V2-4, V2-5 |
| D5 | 기준점 지정 방법 | **데크로 지정할 때 모든 데크에 같은 기준점**(FR0와 중심선 교점 등)을 찍게 한다 | 데크끼리 평면 위치 맞춤 → BOX `decks[].offsetX/offsetY` | V2-2, V2-5 |
| D6 | 2.0 이후 1.x를 유지할까 | **V2-6까지 1.x를 남겨 결과를 비교하고**, 2.0 출시(K6) 뒤 정리한다 | main은 1.x로 계속 배포, v2 → main 병합은 K6에서 한 번 | 전체 |

## V2-0 중 — 개발 방식 (2026-10-25)

사용자: "2.0은 처음부터 개발, 각 프로그램은 기능 참조". 이어서 아래 세 질문에 답함.

| # | 질문 | 결정 | 이 결정이 바꾸는 것 | 단계 |
|---|---|---|---|---|
| D7 | 원본 로직을 잘라 올까, 새로 짤까 | **2.0은 처음부터 새로 짠다.** SketchCAD·BOX CAL·PHG D와 HVAC Grid 1.x의 `lib`(풍량·계통·SOLAS·보고서·DXF)는 **기능 참조**로만 쓴다(코드를 가져오지 않음) | 기획서 4장 원칙 4("잘라 온다")와 `extract:*`·`lib/phg/*` 사본·해시 시험을 대체. V2-1·V2-4·V2-5는 "잘라 오기"가 아니라 "기능 명세 → 새 엔진". 0.3~0.5 조사는 다시 짤 기능 명세(입력·출력·규칙·알고리즘) | V2-1~V2-6 |
| D8 | 새 엔진이 1.x와 같은 답을 내야 하나 | **기능만 같으면 된다.** 1.x 기준값(V2-0)은 비교용 정답지로 쓰고, 값이 다르면 차이와 원인을 기록한다 | G8 "같은 답"을 "같은 기능, 차이는 기록"으로. 단계 완료 기준의 "기준값과 같음"은 "기준값과 비교해 차이 기록·설명" | V2-1~V2-6 |
| — | V2-0을 어떻게 할까 | **계속하되 목적을 바꾼다**: 기준값은 정답지, 조사는 기능 명세, K1에서 멈춤 | | V2-0 |

강제 항목 F-1(풍량은 여름 기준 하나, 겨울은 난방 용량)·F-2(표준 값은 원문 ISO 7547:2022로 확인)는 D8과 관계없이 그대로 적용한다(`AGENTS.md`). 새로 짠 엔진도 겨울 풍량 경로를 두지 않는다.
