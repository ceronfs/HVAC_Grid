# 조사 — SketchCAD 코어와 캔버스 (2.0 기능 명세)

작성 2026-10-25 · V2-0.5 · 대상: 사용자가 올린 `SketchCAD.html`(535,538 B, sha256_16 `880e532b45e60849`, 제목 "PHG SketchCAD 2D", 판·커밋 표시 없음) — `ceronfs/SketchCAD` 저장소는 이 세션에서 읽지 못함 · 방향: D7(2.0은 새로 짠다, SketchCAD는 기능 참조) · D8(같은 기능, 값 차이는 기록)

- 파일은 실행하지 않고 읽기만 했다. 줄 번호는 `SketchCAD.html:<줄>`(위 해시의 파일).
- **판이 저장소 문서보다 옛것이다.** 이 파일에는 ① "계산용으로 열기"(커밋 `8295e36`, 문자열 `계산용으로 열기`·`calcKeepLayers` 0건), ② 실 자동 찾기 속도 수정(`cb6f602`: `findRoomsByText`가 문자마다 `roomAt` → `roomEnts()`로 도면 전체를 다시 훑음, `:7247`·`:7298`), ③ 경계 이름 STR·PNL(`docs/WORKFLOW_SKETCHCAD.md`, `a71025a`)이 없다 — 경계는 **BHD·PANEL**(`:6150`). 이 셋은 저장소 문서(`docs/WORKFLOW_SKETCHCAD.md`, `docs/REVIEW_2026-10-25_BIG_DXF.md`)로만 적는다(5장, 9장).
- 강제 항목: F-1 해당 없음(풍량 코드와 무관한 형상 조사, 2.0 형상 엔진에도 풍량 경로 없음) · F-2 표준 값을 인용하지 않음.

## 1. 결론

| 2.0이 새로 짤 것 | SketchCAD에서 가져올 기능(코드 아님) | 2.0에서 다르게 할 것 |
|---|---|---|
| DXF 읽기(`lib/io/dxf` 또는 `engines/geometry`) | 엔티티 집합(LINE·LWPOLYLINE/POLYLINE 볼록·ARC·CIRCLE·ELLIPSE·SPLINE·TEXT·MTEXT·ATTRIB·INSERT·DIMENSION 블록·HATCH·SOLID), 단위(`$INSUNITS`), OCS 뒤집기, 코드 페이지(UTF-8 → `$DWGCODEPAGE` → EUC-KR 추정), 레이어 표 | 본 화면 동기·파일 전체 문자열 대신 **Worker + 바이트 스트림**, 레이어 개수 먼저 → 고른 레이어만 객체(계산용으로 열기), 객체 대신 **typed array** |
| 계산용 정리·레이어 용도 | 용도 목록(외판·BHD·패널·DECK·실 이름·실 외곽·덕트·제외), 조선소별 이름 규칙, 남길 레이어 판단, 지울 종류(치수·해치), 문자는 남김 | 규칙을 브라우저 설정이 아니라 **모델 `source.mapping`**에, 열기와 정리가 같은 함수 |

| 면적표·경계 길이 | 순면적(구멍 뺌)·총면적·둘레·용도별 경계 길이·개구부 길이, CSV·JSON(`sketchcad-rooms/1`)·HVAC Grid용 DXF | 이웃 실(`boundaries.roomA/roomB`)과 상하 접촉은 **신규** |
| 캔버스 코어 | 보기(중심+축척), 더러움 표시 + rAF 한 번, 바탕·덧그림 두 장, 격자 색인 고르기·스냅, 큰 도면 묶음 그리기·LOD, 명령 줄(약어·키워드 프롬프트) | 이동·확대 중 **비트맵 재사용**, 모듈 층·데크 필터, 실행 취소는 명령 하나(JSON 스냅숏 없음) |

**추정**: V2-5 새 엔진·캔버스 작업은 **약 20~28 작업일**(8장, V2-2를 흡수할 때). 계획서의 10~15일은 "잘라 오기" 전제라 D7 뒤에는 모자란다 — K1에서 고친다. V2-2(SketchCAD 데크 지정)는 D7 뒤 2.0의 "데크로 지정"과 두 번 만드는 일이 되므로 K1에서 D3를 다시 묻는다(7장).

### 3.2 계산용 열기·정리

`openHvClean`(`:6262`), 리본 "① 계산 준비"(`:6384`).

| 규칙 | 내용(이 판) |
|---|---|
| 남길 레이어(처음 체크) | ① 용도가 하나라도 있으면: 용도가 `CALC_PURPOSES`(외판·BHD·패널 3종·DECK·ROOM·ROOM_OUTLINE, `:3737`)이거나 BHD·PANEL 지정 레이어, `EXCL` 제외 ② 용도가 없고 지정 레이어가 있으면: 지정 레이어 + 이름에 `ROOM|실명|NAME` ③ 둘 다 없으면 이름 정규식 `KEEP_PAT`(`BHD|BULK|PANEL|PNL|WALL|PARTITION|격벽|판넬|패널|칸막이|벽|OUTLINE|외곽|DECK|ROOM|실명|NAME`, `:6260`) |
| 남긴 레이어 안에서도 지울 종류 | 치수·해치(기본 켬), 블록 참조·문자(기본 끔) |
| 문자 | "레이어와 관계없이 남김"(기본 켬) — 실 이름 인식용 |
| 처리 | 삭제(기본) 또는 숨기기(`_EXCLUDED` 레이어로 옮겨 끔, 원래 레이어·색은 `prevStyle`에 — 복원 `restoreExcluded` `:6217`) · 삭제 때 빈 레이어·안 쓰는 블록 소거 · 명령 하나(실행 취소) |
| 경고 | 남길 목록에 경계 레이어가 없으면 경고 |
| 매핑 규칙(조선소별) | `DEFAULT_LAYMAP`(`:6598`): `*BHD*,*BULK*,*격벽*`→BHD, `*B-15*`→PANEL_B15, `*B-0*`→PANEL_B0, `*PANEL*,*PNL*,*PARTITION*,*판넬*,*패널*,*칸막이*,*WALL*`→PANEL, `*HULL*,*SHELL*,*외판*`→HULL, `*DECK*,*CEIL*,*갑판*,*천장*`→DECK, `*ROOM*,*실명*,*SPACE*NAME*`→ROOM, `*DIM*,*치수*`→ANNO. 첫 규칙이 이김, 이미 있는 용도는 덮지 않음, 대상 레이어로 합치기 선택, "현재 도면에서 배우기". 규칙은 **브라우저 설정**(`S.layMaps`, localStorage)에 저장 |

2.0 명세: 규칙(정규식·와일드카드·첫 규칙 우선·덮지 않음)은 같게, 저장은 모델 `source.mapping`(다른 PC에서 같은 결과). 숨기기 모드는 2.0에서 필요 없다(원본은 모델에 없음 — 정리 전/후 보기는 원본 래스터 층을 켜고 끄는 것으로).

주의(N3 시험과 같음): `ROOM` 레이어는 SketchCAD가 실 외곽 자리로 쓰고(`isRoomLayer` `:7218`) 경계에서 뺀다. 받은 도면의 벽이 `ROOM`에 있으면 PNL로 옮겨야 실이 찾아진다. 2.0은 실 외곽을 모델 `rooms`에 따로 두므로 이 충돌이 없다 — 받은 도면의 `ROOM` 레이어는 일반 레이어로 다룬다.

**실 자동 찾기** `findRoomsByText`(`:7291`) · `openRoomAuto`(`:7315`):

- 그래프: `roomGraph`(`:7229`) — 경계 용도 선, 없으면 "모든 선"인데 **지금 화면 안의 것만**(`viewRect`, `:7231`) → 결과가 보기에 따라 다름.
- 씨앗: 보이는 문자(실 레이어 제외)의 가운데점. 이미 만든 실 안이면 건너뜀(`roomAt` — 이 판은 문자마다 `roomEnts()`로 전체를 훑음).
- 면 거르기: 면적 0.5 m² 미만·`roomMaxM2`(2,000 m²) 초과 제외. 같은 면(범위·면적·루프 수 키)에 든 문자는 모음.
- 번호: 문자 중 `/^[A-Z]{0,3}[-.]?\d{1,4}[A-Z]?$/i`. 이름: 나머지 문자를 빈칸으로 이음(숫자·면적 표기만인 것 제외). 번호 없는 실은 도면의 가장 큰 번호 + 1. 번호 순(한국어 숫자 비교) 정렬.
- 확인 창: 체크·번호·이름 고침 → "실 만들기" = 실마다 `ROOM` 레이어 닫힌 폴리선 + `room: {no, name, holes, tNo, tName}`, 선택하면 `ROOM-NO`·`ROOM-NAME` 문자(`makeRoom` `:7249`, 글자 위치 `labelPoint` `:7236`).

**실 지정** `cmdRoom`(`:7261`): 안쪽 점 클릭 → 같은 그래프 `query` → 번호(다음 번호 자동 증가 `nextNo`)·이름 입력. 키워드 N(번호)·G(문 틈)·H(문자 높이).

**실 데이터** `roomData`(`:7378`): `{id, no, name, areaM2(순: 외곽 − 구멍), perimeterM, bounds, holes}`. 손으로 그린 외곽(`room` 속성 없음)은 안의 문자를 레이어 이름(`NO|NUM|번호`, `NAME|이름|실명`)·모양으로 번호·이름, 구멍은 `ROOM-HOLE` 레이어에서 되읽음.

**경계 길이** `roomBoundaryLengths`(`:7344`): 실 외곽의 변마다, 같은 직선(방향 차 0.02, 거리 ≤ max(5, 8) mm) 위의 경계 선 구간을 용도별로 합치고, 어느 선에도 없는 구간 = `OPENING`(문). 단위 m.

이 판의 위험 요소(2.0이 피할 것): 15만 선분 잘림(`:5186`), 점마다 모든 반변 훑기(`:5247`), 문자마다 실 목록 다시 만들기(`:7298`), 실마다 경계 원본 다시 거르기(`:7345`), 화면 보기에 기대는 "모든 선" 경로(`:7231`), 편집마다 색인 통째로 다시 만들기(`:792`).

## 6. 2.0 모델과의 대응 (PLAN_V2 6장)

| 모델 | SketchCAD에서 | 빈 곳·바꿀 것 |
|---|---|---|
| `source.files[{name, sha256, layersKept}]` | `doc.name`만. 남긴 레이어는 정리 창의 체크(최신 판: 계산용 열기 선택) | 해시·코드 페이지·단위 배율 기록 신규 |
| `source.mapping` | `S.layMaps` 프리셋(브라우저 설정) `:6598` | 모델에 저장 |
| `decks[{id, name, z, height, origin, rotation, order}]` | 면적표의 데크 이름 칸 하나(`S.roomDeck`). z·층고·기준점 없음 | 전부 신규(V2-2 또는 V2-5 "데크로 지정", D4·D5) |
| `geometry[deck].lines[{a, b, purpose, layer}]` | 객체(`line`·`polyline`·`arc`…) + 레이어 용도 | 선분으로 펼쳐 저장, 용도는 선마다. 문 틈 이은 선 = `OPENING` |
| `geometry[deck].texts` | `text` 객체(MTEXT 포함) | 정리 결과 문자 |
| `rooms[{id, deckId, no, name, polygon, holes, areaM2, volumeM3, isoClass}]` | `roomData`: id(무작위 `uid` `:391`), no, name, 외곽, 구멍, 순면적, 둘레 | `volumeM3`(데크 층고 필요)·`isoClass` 신규. id는 안정적으로(데크 + 번호 또는 첫 생성 id 유지) |
| `boundaries[{kind, roomA, roomB, deckIds, purpose, lengthMm, areaM2, a, b}]` | 실별 용도별 길이 합(`roomBoundaryLengths`) — 이웃 실 모름 | 두 실이 공유하는 변 짝짓기, 외기 면, 위·아래 데크 접촉(BOX `deckStackIssues`) 신규 |
| 좌표 | CAD y 위(+), 화면에서만 뒤집음 | 모델 y 아래(+), `lib/io`에서 뒤집음(원칙 7) |

**이름 충돌**: SketchCAD 용도 `DECK`(갑판·천장 경계선, 평면의 선)와 2.0 `decks`(층: 높이·층고·기준점)·"데크로 지정"이 같은 말이다. PLAN_V2 6장 `purpose: 'DECK'`도 같은 충돌. 제안: 선 용도를 `DECKEDGE`(표시 "갑판 끝·천장선")로 바꾸고 `DECK`은 층에만 쓴다. 1.x·SketchCAD 파일을 읽을 때 `DECK` 용도 → `DECKEDGE`. 사용자 결정 필요(K1).

## 7. V2-2(SketchCAD 데크 지정)와의 관계

D3(2026-10-25 K0)는 "SketchCAD 단독판에도 데크 지정을 넣는다", 이어서 D7은 "2.0은 새로 짜고 SketchCAD는 기능 참조"다. 2.0은 0 `drawing` 모듈에 "데크로 지정"을 어차피 가져야 하므로(PLAN_V2 5.1, V2-5.3) V2-2를 그대로 하면 같은 기능을 두 번 만든다.

| 안 | 내용 | 좋은 점 | 나쁜 점 |
|---|---|---|---|
| A. V2-2 유지(D3 그대로) | SketchCAD 저장소에 데크 표·데크로 지정·필터·`sketchcad-decks/1`, HVAC Grid `lib/io/sketchcad.cjs` → BOX JSON | 1.x 사용자가 K2 무렵(약 20일째)부터 여러 데크 흐름을 씀, 단독판도 혜택, 2.0의 기능 명세·정답지가 먼저 생김 | 4~6일 더(두 번 구현), 형식 `sketchcad-decks/1`을 계속 맞춰야 함, 받은 이 판은 옛것이라 최신 main에서 작업해야 함, 한 파일 여러 데크는 메모리 부담(200 MB에 2.8 GB) |
| B. V2-2를 V2-5에 흡수 | 2.0 0 모듈의 "데크로 지정"만 만든다(8장 5.8, 2~3일) | 한 번 구현, 모델 `decks`에 바로, 이름 충돌을 처음부터 정리, 형식 부담 없음 | 여러 데크 흐름이 V2-5(약 50일째) 뒤에야, 단독판에는 없음, D3를 바꾸는 결정 필요 |
| C. 줄인 V2-2 | SketchCAD에는 데크 표·내보내기만(2~3일), 지정·필터 화면은 2.0에만 | 1.x 경로를 일찍 열면서 화면 중복을 줄임 | 단독판 기능이 반쪽 |

권고: K1에서 D3를 다시 묻는다. 단독판에 데크 지정이 **당장 필요하지 않으면 B**(구현 한 번, 총 작업 4~6일 줄어듦). 필요하면 A로 하되, 2.0 "데크로 지정"은 V2-2의 용어·데크 표 열(이름·z·층고·기준점)을 그대로 따르고 `sketchcad-decks/1`을 `lib/io` 가져오기 형식으로 받는다.

## 9. 확인하지 못한 것

- `ceronfs/SketchCAD` 저장소와 최신 main: 이 세션에 붙지 않았다. 계산용으로 열기(`8295e36`), 실 찾기 수정(`cb6f602`), STR·PNL 이름(`a71025a` 무렵)은 저장소 문서로만 적었다. 받은 파일에는 판·커밋 문자열이 없어 나이는 위 세 가지가 없다는 것으로 추정했다.
- 실행·측정: 파일을 실행하지 않았다. 5장 시간·메모리는 모두 `docs/WORKFLOW_SKETCHCAD.md`·`docs/REVIEW_2026-10-25_BIG_DXF.md`(최신 판, 합성 도면)의 값이다.
- 최신 판이 Worker·스트림 해석을 쓰는지: 모른다. "해석 중 최대 741 MB(줄 배열·코드 쌍 배열)"로 보아 여전히 본 화면 전체 문자열 해석으로 보인다.
- 최신 판의 DECK 용도 뜻·HVAC Grid용 DXF가 용도를 담는지(이 판의 R12 쓰기는 담지 않음).
- 실제 조선소 일반배치도(합성 도면과 N3만 기록에 있음).
- 작업일 추정은 이 조사만의 추정이며 K1에서 V2-0 다른 조사(0.3 CAL, 0.4 PHG)와 함께 다시 정한다.
