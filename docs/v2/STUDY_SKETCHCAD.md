### 3.2 계산용으로 열기·계산용 정리

**계산용으로 열기**(`8295e36`, `:4944`–`:4986`, 사용 `:4901`–`:4916`):

| 단계 | 내용 |
|---|---|
| 조건 | 파일 바이트 ≥ `CALC_OPEN_BYTES` = 16e6(`:4948`). 그보다 작으면 전과 같이 바로 연다 |

| 레이어 요약 | `dxfLayerSummary`(`:4958`): 모형 공간 엔티티 레코드를 레이어별로 셈(블록 정의 안은 세지 않음), 용도 = 레이어 표의 XDATA 또는 지금 매핑 규칙의 용도(`rulePurpose` `:4951`) |

주의(N3 시험과 같음): `ROOM` 레이어는 SketchCAD가 실 외곽 자리로 쓰고(`isRoomLayer` `:7304`) 경계에서 뺀다. 받은 도면의 벽이 `ROOM`에 있으면 PNL로 옮겨야 실이 찾아진다. 2.0은 실 외곽을 모델 `rooms`에 따로 두므로 이 충돌이 없다 — 받은 도면의 `ROOM` 레이어는 일반 레이어로 다룬다.

### 3.4 실 찾기

**경계 그래프** `boundaryGraph(ents, gap)`(`:5251`) — 한 번 만들고 점마다 `query`(옛 파일과 같은 코드):

|---|---|---|

**실 자동 찾기** `findRoomsByText`(`:7378`) · `openRoomAuto`(`:7402`):

- 그래프: `roomGraph`(`:7315`) — 경계 용도 선, 없으면 "모든 선"인데 **지금 화면 안의 것만**(`viewRect`, `:7317`) → 결과가 보기에 따라 다름.
- 씨앗: 보이는 문자(실 레이어 제외)의 가운데점. 이미 만든 실 안이면 건너뜀. **`cb6f602`**: 실 외곽 목록 `roomEnts()`를 한 번만 만들어(`rooms0` `:7381`) `roomAt(p, rooms)`(`:7335`)에 넘긴다 — 옛 파일은 문자마다 도면 전체(100 MB에 객체 약 100만)를 훑었다.
- 면 거르기: 면적 0.5 m² 미만·`roomMaxM2`(2,000 m²) 초과 제외. 같은 면(범위·면적·루프 수 키)에 든 문자는 모음.
- 번호: 문자 중 `/^[A-Z]{0,3}[-.]?\d{1,4}[A-Z]?$/i`. 이름: 나머지 문자를 빈칸으로 이음(숫자·면적 표기만인 것 제외). 번호 없는 실은 도면의 가장 큰 번호 + 1. 번호 순(한국어 숫자 비교) 정렬.
- 확인 창: 체크·번호·이름 고침 → "실 만들기" = 실마다 `ROOM` 레이어 닫힌 폴리선 + `room: {no, name, holes, tNo, tName}`, 선택하면 `ROOM-NO`·`ROOM-NAME` 문자(`makeRoom` `:7336`, 글자 위치 `labelPoint` `:7322`).

**실 지정** `cmdRoom`(`:7348`): 안쪽 점 클릭 → 같은 그래프 `query` → 번호(다음 번호 자동 증가 `nextNo`)·이름 입력. 키워드 N(번호)·G(문 틈)·H(문자 높이).

**실 데이터** `roomData`(`:7465`): `{id, no, name, areaM2(순: 외곽 − 구멍), perimeterM, bounds, holes}`. **`cb6f602`**: 경계 원본·실 목록·`ROOM-HOLE` 구멍·문자를 실마다가 아니라 한 번만 거름(`:7466`–`:7469`). 손으로 그린 외곽(`room` 속성 없음)은 안의 문자를 레이어 이름(`NO|NUM|번호`, `NAME|이름|실명`)·모양으로 번호·이름, 구멍은 `ROOM-HOLE`에서 되읽음.

**경계 길이** `roomBoundaryLengths(r, holes, src)`(`:7431`): 실 외곽의 변마다, 같은 직선(방향 차 0.02, 거리 ≤ max(5, 8) mm) 위의 경계 선 구간을 용도(STR·PNL·DECK, 용도 없으면 레이어 이름)별로 합치고, 어느 선에도 없는 구간 = `OPENING`(문). 단위 m. 원본은 한 번 거른 목록을 받지만, 실마다 그 목록 전체를 bbox로 다시 훑는다(실 수 × 경계 객체 수).

## 6. 2.0 모델과의 대응 (PLAN_V2 6장)

| 모델 | SketchCAD에서 | 빈 곳·바꿀 것 |
|---|---|---|
| `source.files[{name, sha256, layersKept}]` | `doc.name`만. 남긴 레이어 = 계산용 열기 선택(`chooseCalcOpen`) 또는 정리 창의 체크 | 해시·코드 페이지·단위 배율·읽지 않은 객체 수(`leftOut`) 기록 |
| `source.mapping` | `S.layMaps` 프리셋(브라우저 설정) `:6677` | 모델에 저장 |
| `decks[{id, name, z, height, origin, rotation, order}]` | 면적표의 데크 이름 칸 하나(`S.roomDeck`). z·층고·기준점 없음 | 전부 신규(V2-2 또는 V2-5 "데크로 지정", D4·D5) |

**이름 충돌**: SketchCAD 용도 `DECK`(갑판·천장 경계선, 평면의 선 — main에서도 그대로, `DECK_OUTLINE`만 STR로 감)와 2.0 `decks`(층: 높이·층고·기준점)·"데크로 지정"이 같은 말이다. PLAN_V2 6장 `purpose: 'DECK'`도 같은 충돌. 제안: 선 용도를 `DECKEDGE`(표시 "갑판 끝·천장선")로 바꾸고 `DECK`은 층에만 쓴다. 1.x·SketchCAD 파일을 읽을 때 `DECK` 용도 → `DECKEDGE`(SketchCAD가 BHD → STR을 읽기 표로 흡수한 것과 같은 방식). 사용자 결정 필요(K1).

## 7. V2-2(SketchCAD 데크 지정)와의 관계

D3(2026-10-25 K0)는 "SketchCAD 단독판에도 데크 지정을 넣는다", 이어서 D7은 "2.0은 새로 짜고 SketchCAD는 기능 참조"다. 2.0은 0 `drawing` 모듈에 "데크로 지정"을 어차피 가져야 하므로(PLAN_V2 5.1, V2-5.3) V2-2를 그대로 하면 같은 기능을 두 번 만든다. main(`3df0ba8`)에는 아직 데크 표·데크로 지정이 없다(데크는 면적표의 이름 칸 하나).

| 안 | 내용 | 좋은 점 | 나쁜 점 |
|---|---|---|---|
| A. V2-2 유지(D3 그대로) | SketchCAD main에 데크 표·데크로 지정·필터·`sketchcad-decks/1`, HVAC Grid `lib/io/sketchcad.cjs` → BOX JSON | 1.x 사용자가 K2 무렵(약 20일째)부터 여러 데크 흐름을 씀, 단독판도 혜택, 2.0의 기능 명세·정답지가 먼저 생김 | 4~6일 더(두 번 구현), 형식 `sketchcad-decks/1`을 계속 맞춰야 함, 한 파일 여러 데크는 메모리 부담(데크마다 계산용으로 열기가 필요) |
| B. V2-2를 V2-5에 흡수 | 2.0 0 모듈의 "데크로 지정"만 만든다(8장 5.8, 2~3일) | 한 번 구현, 모델 `decks`에 바로, 이름 충돌을 처음부터 정리, 형식 부담 없음 | 여러 데크 흐름이 V2-5(약 50일째) 뒤에야, 단독판에는 없음, D3를 바꾸는 결정 필요 |
| C. 줄인 V2-2 | SketchCAD에는 데크 표·내보내기만(2~3일), 지정·필터 화면은 2.0에만 | 1.x 경로를 일찍 열면서 화면 중복을 줄임 | 단독판 기능이 반쪽 |

권고: K1에서 D3를 다시 묻는다. 단독판에 데크 지정이 **당장 필요하지 않으면 B**(구현 한 번, 총 작업 4~6일 줄어듦). 필요하면 A로 하되, 2.0 "데크로 지정"은 V2-2의 용어·데크 표 열(이름·z·층고·기준점)을 그대로 따르고 `sketchcad-decks/1`을 `lib/io` 가져오기 형식으로 받는다.
