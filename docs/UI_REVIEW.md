# UI 통합 검토 — BOX CAL Enhance × PHG D

작성 2026-10-18 · 대상: `vendor/BOX_CAL_Enhance.html`(bd942611), `vendor/DuctConcept_PHG_D.html`(643f328a) — 원본은 수정하지 않음
캡처: `docs/ui/box-*.png`, `docs/ui/phg-*.png` (`probe/ui-capture.cjs`) · 목업: `docs/ui/mockup.html`(`node tools/build-mockup.cjs`), 캡처 `docs/ui/mockup-*.png` (`probe/mockup-capture.cjs`)
디자이너 검토: `docs/UI_DESIGN_REVIEW.md`

## 1. 결론

**통합할 수 있다.** 두 앱은 겉보기가 다르지만 뼈대가 같다 — 같은 NODE 색·글꼴 토큰, "위 명령줄 + 왼쪽·오른쪽 패널 + 가운데 도면" 배치. 다른 것은 **명령 표기**(BOX 2글자 코드 vs PHG D 아이콘·한글 리본)와 **작업 흐름**(BOX CAL이 전체 화면 창으로 따로 뜸)이다.
→ 작업 순서를 앞에 세운 **하나의 셸**(단계 표시 + 단계별 리본 + 공통 Deck·격실 트리 + 공통 속성 패널)을 만들고, 가운데 도면만 단계에 따라 BOX 또는 PHG D 화면을 쓴다.

## 3. BOX 코드 → 셸 명령 (단계 ①②)

| 셸 그룹 | 셸 명령 (BOX 코드) |
|---|---|

단계 ④는 PHG D 리본(계통 · 자동 라우팅 · 덕트 · 계산)을 그대로 쓴다. 단계 ③⑤는 새 명령(풍량 규칙, 계통 배정, 공조기 위치, BOX 반영 / 풍속·압력·소음·방화, 통합 출력).

## 4. 구현 방식

| 단계 | 방식 | 원본 수정 |
|---|---|---|
| **S1 셸 (이번)** | `app/` 셸이 두 앱(`vendor/` 사본)을 같은 출처 iframe으로 띄움(`npm start` → 로컬 서버). 셸 리본 → iframe 안 원래 버튼 실행, CSS 주입으로 원래 명령줄 숨김. 계약(hvac-grid/0)은 셸이 BOX에서 바로 읽고, PHG D로 Deck·계통을 보냄 | 없음 |
| S2 공통 트리·속성 | 트리·속성 패널이 두 앱 상태를 계약으로 동기화(선택 격실 ↔ 도면 강조) | 없음 |
| S3 단일 앱 (H5) | 공통 모델 위에 BOX 계산·PHG D 덕트 모듈 | — |

- `file://`로 열면 iframe 안을 스크립트로 다룰 수 없음(브라우저 보안) → 로컬 서버 필요(이전 HVAC Studio와 같음, 127.0.0.1에만 열림).
- 원래 명령줄을 숨겨도 두 앱의 단축키·대화상자는 그대로 동작.

## 6. 통합 셸 S1 — 실제 동작 (`app/`)

목업 다음 단계로 **실제로 동작하는 셸**을 만들었습니다(`npm start` → `http://127.0.0.1:8792/app/`). 두 앱은 `vendor/` 사본 그대로 iframe에서 돌고, 셸이 원래 명령줄만 숨기고(CSS 주입) 명령·데이터를 연결합니다(`app/bridge.js`).

| 단계 | 화면 | 동작 |
|---|---|---|
| ① 도면·격실 | BOX 화면 + 셸 리본(파일·보기·격실·검사·예제) | 리본 → BOX 원래 버튼, 파일은 셸에서 골라 BOX 입력으로 전달 |
| ② 부하 | BOX CAL + 셸 리본(조건·K값·부하·내보내기) | CAL 명령 → CAL 내부 앱의 명령(표는 BOX 방식대로 새 창), **계약 만들기** → BOX 격실·부하를 계약으로 읽음(S5 94실 약 0.5초) |
| ③ 풍량·계통 | 셸 평면(계약 데이터) | 급기 ΔT 적용(풍량·계통 합계 다시 계산), 계통별 **공조기 위치 지정**(평면 클릭), 계약 저장·열기 |
| ④ RU·덕트 | PHG D 화면 + 셸 리본 | Deck·계통 고르고 **PHG D로 보내기**(격실 도면 + 공조기 + 격실별 RU), **보내기 + AUTO**(덕트 지정·계산·압력까지), 결과 읽기, PHG D 원래 명령 |
| ⑤ 검토·출력 | 요약 표 + 검토 목록 | 모든 계통 AUTO, Deck·계통별 RU·풍량·덕트·길이·압력손실, 프로젝트 저장(계약 + PHG D 프로젝트), 요약 CSV |

S5 결과: 셸에서 10계통 모두 AUTO — RU 100개 전부 연결, 풍량 RU 합 = 설계 풍량, 길이·압력손실이 H1 도구 결과와 같음. 캡처: `docs/ui/shell-*.png` (`probe/shell-capture.cjs`), E2E `npm run test:e2e`.

| 8 공간 | 패널 접기, 1366 px 이하 208/256 px, 리본 가로 스크롤(1280 px에서 ③ 넘침 0), 범례 오른쪽 위로, PHG D 오른쪽 패널 기본 닫힘(셸 속성 패널과 중복; ④ 리본 "패널"에서 열기) | ✅ 일부 (폭 드래그 조절은 S2) |

그 밖에 반영: 트리 값 열이 단계를 따름(① m² ② W ③~⑤ CMH) + 열 머리, 계통 색 점은 ③부터, 필터 칩에 개수, 속성 카드 순서 고정(형상 → 부하 → 풍량 → 계통 → RU·덕트)과 현재 단계 카드 강조, 용어 급기(SA)·환기(RA)·배기(EA)·신기(OA), 수식 문장형, 상태 줄 "선박 전체:" 접두어와 선택 정보.

**S2 이후로 미룬 것**: 명령 검색(Ctrl+K, 코드 별칭), 리본 2단 작은 버튼·넘침 접기, 레이어 탭·Deck 카드(Z·H 편집), 도크 폭 드래그, ② 하단 표 패널(현재는 BOX CAL 표가 새 창), ⑤ 문제 마커, 프레임 번호 눈금자·FWD 표시, 테마를 두 앱에 전달, 선택 격실 ↔ BOX 도면 강조 동기화. 사용성 테스트(검토 6장)는 S2 화면으로.
