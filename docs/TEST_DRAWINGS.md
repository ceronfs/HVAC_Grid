# 시험 도면 — T3 시험선 · N3 시험선

작성 2026-10-19 · v2.6 (BOX ISO 계산 방식, 2026-10-21) · v2.5 (ISO 7547:2022 대조, 2026-10-21) · v2.4 (경계 조건) · v2.3 (창 일사) · v2.2 (화장실 번호) · v2.1 (2차 리뷰 반영) · 생성 `tools/make-test-ship.cjs` (`npm run make:t3`) · 결과 `samples/t3/`, `samples/t3.contract.json`

S5(BOX 내장 예제)는 계통이 모두 한 Deck이고 실이 직사각형뿐이라 H2~H4 기능을 시험할 수 없습니다. T3는 그 빈자리를 채우는 **합성 시험선**입니다. 실제 호선 설계가 아닙니다.

## 1. 선박

화물선 거주구 4층, 20 × 16 m (항해선교 갑판은 12 × 16 m), 갑판 높이 2,800 mm, 79실(L자 선실 14실), 천장 높이 2,200 mm(식당 2,300, 조리실 2,400, 조타실 2,600; 창고·케이싱은 천장 없음). 좌표는 BOX와 같이 +x 선수, +y 좌현: y 0~7,000 우현 쪽, 7,000~9,000 복도, 9,000~16,000 좌현 쪽.

| Deck | Z (mm) | 실 | 내용 |
|---|---|---|---|
| D4 NAV BRG DK | 8,400 | 10 | 조타실(96 m²), 해도실, 무선실, 배터리실(EF-BAT 독립 배기, 팬은 배터리실 안), 도선사실, 항해장비실(제어장소), 선교화장실, 선교팬룸(AHU-BRG) |
| D3 B DK | 5,600 | 22 | 선장실·기관장실(큰 L자) 등 사관 6실 + 각 화장실(361~363, 371~373), 선박사무실, 회의실, 문서보관실, 선원사무실 |
| D2 A DK | 2,800 | 27 | 선원침실 8실(L자) + 각 화장실(261~265, 271~273), 체육실, 린넨창고, 건조실, 취미실, 선원휴게실 |
| D1 UPPER DK | 0 | 20 | 조리실, 선원·사관식당(14·17인), 배식실(EF-PAN), 세탁실, 세제·린넨 창고, CO2실(EF-CO2 독립 배기, 팬은 CO2실 안), 탈의실, 식료품창고·냉장고, **공조기실**(AHU-ACC·EF-LAU·EF-SAN·RA-ACC), **조리실 팬룸**(SF-GAL·EF-GAL) |

D1~D3 공통 코어: **기관실 케이싱**(복도에 면함, A-60), 선수까지 이어진 **복도**, 계단실(D4 선교 계단과 같은 위치로 **4층 적층** → 복도와 A-0), **덕트 트렁크**(복도·공조기실에 면함), 공용화장실(복도에 면함), 청소도구실·린넨로커.

v2.2에서 바꾼 것: 선실 화장실 번호를 "211T"에서 **선실 번호 + 50**(211 → 261, 323 → 373)으로. BOX는 DXF 문자 중 숫자로만 된 것만 실 번호로 읽어서, "211T"는 실 이름 앞에 붙고 번호는 비었습니다(격실 목록에 "미지정"). 배치·계통·부하·풍량은 v2.1과 같습니다. 이제 Deck별 DXF와 T3_ALL.dxf를 BOX "DXF 열기"로 열면 79실 모두 번호·이름이 들어옵니다. 같은 v2.2에서 DXF와 BOX 프로젝트(`T3.box.json`, ① "T3 시험선")의 벽을 실제 도면처럼 **LINE만**으로 바꿨습니다. BOX 프로젝트의 실 번호·이름은 TEXT이고, 계통·인원·장비 같은 실 데이터는 BOX가 선으로 찾은 실의 id(번호 TEXT의 id)에 붙인 `overrides.roomOverrides`에 있습니다(`tools/t3-box-lines.cjs`가 BOX로 확인하며 만듦). 설계 데이터는 RECT 판과 79실 모두 같습니다(폴리라인·박스 없음, 벽 한 번씩, T자 접합) — BOX·PHG D가 선만으로 실을 찾는지 시험합니다(BOX 79/79, PHG D 실 인식 그대로).

v2.6에서 바꾼 것(2026-10-21, BOX 사본 패치 J·O~U와 함께): 프로젝트 설계 조건에 일사 방식 "노출 상부 갑판 + 최대 외벽"(ISO 7547 5.3)과 "주광 실 조명 무시"(5.5), 조리실 활동도 경작업(표 4, 85/150 W). BOX가 창 전도를 유리 + 200 mm로 계산(5.2.1). 현열 81.8 → 84.5 kW, 난방 52.6 → 54.8 kW, 급기 25,600 → 26,350 CMH.

v2.5에서 바꾼 것(2026-10-21, ISO 7547:2022 원문 대조 — `docs/ISO7547_CHECK.md`): 실내 여름 설계 조건을 **25 °C / 55 %**로 되돌림(4.2 b) — v2.4의 27/50은 2002판 값을 표준으로 잘못 안 것). 급기 없는 실의 온도를 표 1 ΔT로(창고·팬룸·트렁크·로커·CO₂·축전지실 27/17 °C, 선실 화장실 26/22, 공용·선교 화장실 31/22), 최하층 바닥 K 0.8(표 2 #2). 인원을 4.5로(식당 1.5 m²/인 → 14·17인, 오락실 5 m²/인, 사무실 2, 체육실 4, 선장·기관장실 4, 조타실 5), 주광 실 조명 0(5.5), 체육실 10 W/m², 무선실 2.5 kW, 조타실 장비 2 kW(D.3.3). 배기를 6.4.1·6.4.2로: 건조실 25회/h + 급기, 배식실 28회/h·단독 배기 EF-PAN, 조리실 48회/h. 냉방 현열 89.5 → 81.8 kW, 난방 53.9 → 52.6 kW, 급기 27,980 → 25,600 CMH, 계획 17 → 18.

v2.4에서 바꾼 것(2026-10-20 검토 L3·L5): 최하층(UPPER DK) 바닥 아래를 기관실로(BOX 면 경계 NON_AC 43/5 °C — 전에는 외기 35/−20 °C), 기관실 케이싱 43/5 °C(BOX S5 기관 공간과 같음), 계통 없는 창고·팬룸·공조기실·트렁크는 비공조(NON_AC, 32/10 °C). T3 난방 60.2 → 53.9 kW. 세탁실 배기 40 → 45회/h. 같은 v2.4에서 실내 설계 조건을 27 °C / 50 %로(전 25 °C / 55 % — **v2.5에서 되돌림**: 2022판 4.2 b)는 25 °C / 55 %), 외기 잠열은 BOX 습공기 모델(humidity)로 — 냉방 현열 92.3 → 89.5 kW.

v2.3에서 바꾼 것(2026-10-20 검토 L1): 창문 일사를 BOX S5 예제와 같은 `windowSolarMode: auto-double-interior-shade`(ISO 7547:2022 5.3, 투명 복층 + 내부 차양 Gs 240 W/m²)로. 전에는 실별 기본값(수동 0 W/m²)이라 29실 56.8 m² 창의 일사가 0이었음. T3 냉방 현열 75.8 → 88.7 kW, 조타실 9.45 → 13.75 kW. 급기가 늘어 조리실 배기 45 → 50회/h, 배식실 20 → 22회/h로 올려 부압(배기 > 급기)을 유지.

3차 리뷰 반영(같은 v2.1 배치): 배식실(조리기구 없음) 배기를 EF-GAL에서 EF-SAN으로 — 조리실 계통이 식당·휴게실을 지나지 않음. DXF에 `$DWGCODEPAGE`·LAYER 표 핸들·하위 클래스 추가(ezdxf recover 오류 0).

v2.1에서 바꾼 것(리뷰 2차 R2-ENG-03·05): 실별 천장 높이(체적·환기 횟수가 천장 기준), 조리실 팬룸 분리, 세탁실·탈의실·선원식당 재배치, 건조실을 복도에 면하게. 조리실 환기 45회/h, 배식실 20회/h(배기 > 급기 부압 유지).

v2에서 바꾼 것(리뷰 1차 R1-T3-01·02): 공조기실·트렁크·공용화장실이 복도에 직접 면하도록 배치(덕트가 케이싱·계단을 지날 이유가 없음), 축전지실·CO2실 독립 배기, 세탁실 급기, 선교 팬룸 확대(15.75 m²), 조타실 내부 발열·창 면적 상향.

# N3 시험선 — 도면부터 시작 (2026-10-22)

생성 `tools/make-test-ship3.cjs [outDir] [seed]` · 실행 `test/e2e/n3.e2e.cjs [seed]`(`npm run test:n3`: 오늘 날짜가 시드) · 기본 세트 `samples/n3`(시드 20261023, `npm run make:n3`)

T3는 BOX 프로젝트(JSON)로 시작해 BOX의 DXF 경로·Deck 지정·외곽선·격실 입력 단계를 거치지 않습니다. N3는 **설계자가 실제로 시작하는 방식** — 일반배치도 DXF 3장 — 으로 HVAC Grid 전체를 돕니다. 같은 시드는 같은 파일. 합성 데이터이며 실제 호선이 아닙니다.

**시드가 바꾸는 것**

| 구분 | 변형 |
|---|---|
| 외곽선(아웃라인) | 선수: 직각 · 모따기(2~3 m) · 테이퍼(앞 5~7 m에서 양현 1.5~2.5 m 좁아짐) · 곡선(타원 선수를 직선 5개씩으로, 2 m 평면 선수재). 3층: 같은 길이 또는 3~5 m 짧은 계단형. 선수 쪽 실은 선체선에 맞춰 잘림(벽이 비스듬한 외곽선과 T자로 만남) |
| 내부(인라인) | 복도: 일직선 · 한쪽으로 치우침(4.5~7.5 m) · 각 Deck 앞 블록에서 0.5~1 m 꺾임(jog). 조리실·의무실 좌현/우현, 선실 폭 3.0~3.5 m(사관 4.0~4.5 m), 길이 22~26 m |

**20일 계획 (`PLAN20`)**: 2026-10-23부터 20일은 선수 4가지 × 계단형 여부 × 복도 3가지 중 서로 다른 20개 조합을 날짜에 고정 배정(이웃한 날은 선수·계단·복도가 모두 다르게). 그 밖의 날짜·시드는 시드로 섞음. 생성기 점검: 70개 시드에서 실 면적 합 = 외곽선 면적, 2 m² 미만 조각 없음, 실 번호 중복 없음, DXF를 다시 읽으면 실 번호·이름·면적 일치.

## 실행 단계 (`test/e2e/n3.e2e.cjs`)

1. ① DXF 3장 → BOX(Deck 3개), Deck 이름·Z·높이를 Deck 목록에 입력, 외곽선의 모든 변(4·6·14개)을 하부·상부 외곽선(OL)으로 지정 — 실 꼭짓점에서 떨어진 점을 클릭(BOX 좌표는 도면의 −y)
2. ② CAL 격실 입력 표에 입력값 붙여넣기(엑셀 붙여넣기 경로), 설계 조건에서 흘수선 미적용, CAL 격실 부하 표, 설계 데이터 만들기 — 모든 실 부하 계산 완료
3. ③ 풍량(여름 풍량 하나, AGENTS.md F-1), 의무실 배기팬 **위치 지정**(린넨창고 클릭)
4. ⑤ 최하층 아래 = 기관실 A류, ④ 모든 계통 AUTO, 검토
5. 출력(프로젝트·XLSX·DXF·보고서), 프로젝트 저장 → 다시 열기
6. 내내: 페이지 오류 0, **BOX가 만든 Deck id("D1792…0.42…")가 화면·보고서·XLSX·DXF에 나오지 않음**

결과: `out/n3/<시드>/summary.md` — "프로그램 이상"(실패 단계·페이지 오류·id 노출)과 "설계 확인 사항"(규칙이 잡은 것, 배치·입력에 따름)을 나눠 적음. 스크린샷과 출력 파일도 같은 폴더.

## 클라우드 정기 실행 (리눅스, Edge 없음)

`bash tools/cloud-n3.sh [--publish]` — 설치(`npm ci`), 브라우저 찾기, 오늘(한국 날짜) 시드로 N3 실행, 끝에 `summary.md`를 출력. `--publish`: PPT·summary.md·캡처를 브랜치 `claude/n3-report`에 올림(커밋 하나를 강제 푸시 — 최신 보고서만 남아 저장소가 커지지 않음). 브라우저: Edge가 없으면 실행기에 미리 설치된 Chromium(`PLAYWRIGHT_BROWSERS_PATH`·`/opt/pw-browsers`)을 쓰고, 없을 때만 내려받음 — 클라우드 실행기는 Playwright 내려받기 주소(cdn.playwright.dev)를 막음(2026-10-22 첫 실행).
