# 시험 도면 — T3 시험선

작성 2026-10-19 · v2.3 (창 일사) · v2.2 (화장실 번호) · v2.1 (2차 리뷰 반영) · 생성 `tools/make-test-ship.cjs` (`npm run make:t3`) · 결과 `samples/t3/`, `samples/t3.contract.json`

S5(BOX 내장 예제)는 계통이 모두 한 Deck이고 실이 직사각형뿐이라 H2~H4 기능을 시험할 수 없습니다. T3는 그 빈자리를 채우는 **합성 시험선**입니다. 실제 호선 설계가 아닙니다.

## 1. 선박

화물선 거주구 4층, 20 × 16 m (항해선교 갑판은 12 × 16 m), 갑판 높이 2,800 mm, 79실(L자 선실 14실), 천장 높이 2,200 mm(식당 2,300, 조리실 2,400, 조타실 2,600; 창고·케이싱은 천장 없음). 좌표는 BOX와 같이 +x 선수, +y 좌현: y 0~7,000 우현 쪽, 7,000~9,000 복도, 9,000~16,000 좌현 쪽.

| Deck | Z (mm) | 실 | 내용 |
|---|---|---|---|
| D4 NAV BRG DK | 8,400 | 10 | 조타실(96 m²), 해도실, 무선실, 배터리실(EF-BAT 독립 배기, 팬은 배터리실 안), 도선사실, 항해장비실(제어장소), 선교화장실, 선교팬룸(AHU-BRG) |
| D3 B DK | 5,600 | 22 | 선장실·기관장실(큰 L자) 등 사관 6실 + 각 화장실(361~363, 371~373), 선박사무실, 회의실, 문서보관실, 선원사무실 |
| D2 A DK | 2,800 | 27 | 선원침실 8실(L자) + 각 화장실(261~265, 271~273), 체육실, 린넨창고, 건조실, 취미실, 선원휴게실 |
| D1 UPPER DK | 0 | 20 | 조리실, 선원·사관식당(12인), 배식실, 세탁실, 세제·린넨 창고, CO2실(EF-CO2 독립 배기, 팬은 CO2실 안), 탈의실, 식료품창고·냉장고, **공조기실**(AHU-ACC·EF-LAU·EF-SAN·RA-ACC), **조리실 팬룸**(SF-GAL·EF-GAL) |

D1~D3 공통 코어: **기관실 케이싱**(복도에 면함, A-60), 선수까지 이어진 **복도**, 계단실(D4 선교 계단과 같은 위치로 **4층 적층** → 복도와 A-0), **덕트 트렁크**(복도·공조기실에 면함), 공용화장실(복도에 면함), 청소도구실·린넨로커.

v2.2에서 바꾼 것: 선실 화장실 번호를 "211T"에서 **선실 번호 + 50**(211 → 261, 323 → 373)으로. BOX는 DXF 문자 중 숫자로만 된 것만 실 번호로 읽어서, "211T"는 실 이름 앞에 붙고 번호는 비었습니다(격실 목록에 "미지정"). 배치·계통·부하·풍량은 v2.1과 같습니다. 이제 Deck별 DXF와 T3_ALL.dxf를 BOX "DXF 열기"로 열면 79실 모두 번호·이름이 들어옵니다. 같은 v2.2에서 DXF와 BOX 프로젝트(`T3.box.json`, ① "T3 시험선")의 벽을 실제 도면처럼 **LINE만**으로 바꿨습니다. BOX 프로젝트의 실 번호·이름은 TEXT이고, 계통·인원·장비 같은 실 데이터는 BOX가 선으로 찾은 실의 id(번호 TEXT의 id)에 붙인 `overrides.roomOverrides`에 있습니다(`tools/t3-box-lines.cjs`가 BOX로 확인하며 만듦). 설계 데이터는 RECT 판과 79실 모두 같습니다(폴리라인·박스 없음, 벽 한 번씩, T자 접합) — BOX·PHG D가 선만으로 실을 찾는지 시험합니다(BOX 79/79, PHG D 실 인식 그대로).

v2.3에서 바꾼 것(2026-10-20 검토 L1): 창문 일사를 BOX S5 예제와 같은 `windowSolarMode: auto-double-interior-shade`(ISO 7547:2022 5.3, 투명 복층 + 내부 차양 Gs 240 W/m²)로. 전에는 실별 기본값(수동 0 W/m²)이라 29실 56.8 m² 창의 일사가 0이었음. T3 냉방 현열 75.8 → 88.7 kW, 조타실 9.45 → 13.75 kW. 급기가 늘어 조리실 배기 45 → 50회/h, 배식실 20 → 22회/h로 올려 부압(배기 > 급기)을 유지.

3차 리뷰 반영(같은 v2.1 배치): 배식실(조리기구 없음) 배기를 EF-GAL에서 EF-SAN으로 — 조리실 계통이 식당·휴게실을 지나지 않음. DXF에 `$DWGCODEPAGE`·LAYER 표 핸들·하위 클래스 추가(ezdxf recover 오류 0).

v2.1에서 바꾼 것(리뷰 2차 R2-ENG-03·05): 실별 천장 높이(체적·환기 횟수가 천장 기준), 조리실 팬룸 분리, 세탁실·탈의실·선원식당 재배치, 건조실을 복도에 면하게. 조리실 환기 45회/h, 배식실 20회/h(배기 > 급기 부압 유지).

v2에서 바꾼 것(리뷰 1차 R1-T3-01·02): 공조기실·트렁크·공용화장실이 복도에 직접 면하도록 배치(덕트가 케이싱·계단을 지날 이유가 없음), 축전지실·CO2실 독립 배기, 세탁실 급기, 선교 팬룸 확대(15.75 m²), 조타실 내부 발열·창 면적 상향.

## 2. 계통 (BOX 실 데이터의 sup / exh / ret)

| 계통 | 종류 | Deck | 담당 | 시험하는 것 |
|---|---|---|---|---|
| AHU-ACC | 급기 | D1·D2·D3 | 거주구 전체 | 다층 계통: 공조기 D1 공조기실, D2·D3는 트렁크 샤프트, 수직 덕트 2구간, 구역 수지(전달 공기 보충) |
| RA-ACC | 환기 | D1·D2·D3 | 선실·식당·복도·사무실 | 다층 환기(배기 모드 압력), 구역 수지로 정한 환기량 |
| EF-SAN | 배기 | D1·D2·D3 | 화장실·탈의실·청소도구실·건조실·배식실 | 다층 배기, 화장실은 배기만(전달 공기) |
| SF-GAL / EF-GAL | 급기 / 배기 | D1 | 조리실 | 조리실 전용(9.7.2.1), 부압(배기 > 급기, 부족분은 식당에서), 9.7.5 점검표 |
| EF-LAU / EF-CO2 | 배기 | D1 | 세탁실 / CO2실 | 단독 배기, CO2실은 자체 흡입구 |
| AHU-BRG / RA-BRG / EF-BRG / EF-BAT | 급기 / 환기 / 배기 / 배기 | D4 | 선교 | 별도 공조기, 축전지실 독립 배기 |

## 3. 파일

| 파일 | 내용 | 쓰는 곳 |
|---|---|---|
| `T3.box.json` | BOX CAL 프로젝트(`NODE-BOX-L4` v2). BOX 내장 S5 예제와 같은 형식: Deck 외곽 LINE + RECT/POLY 격실(실 번호·이름·부하 입력·계통). 설계 조건은 BOX의 S5 설정 | BOX `JSON 열기`, 셸 ① `T3 시험선` |
| `T3_D1.dxf` ~ `T3_D4.dxf` | Deck별 일반배치도: 벽은 **LINE만**(폴리라인·박스 없음, 벽마다 한 번, 여러 실을 지나는 벽은 한 줄이고 다른 벽이 T자로 만남) — 선체 쪽 `DECK_OUTLINE`, 나머지 `ROOM`; `ROOM_NO`·`ROOM_NAME`(TEXT), `TITLE`. DXF 2007(AC1021, 문자 UTF-8), 엔티티마다 하위 클래스 표시(AcDbEntity·AcDbLine·AcDbText) | PHG D·BOX DXF 가져오기, `tools/dxf-check.cjs` |
| `T3_ALL.dxf` | 4개 Deck을 25 m 간격으로 나란히 | 전체 검토 |
| `T3.solas.json` | SOLAS 설정: 최하층 아래 = A류 기관구역 | `tools/hvac-run.cjs --solas=` |
| `../t3.contract.json` | BOX가 계산한 설계 데이터(`tools/box-extract.cjs`) | 셸 `T3 시험선` 설계 데이터, 테스트 |
| `../fixtures/offset-deck.*` | Deck 하나를 90° 회전·변위한 BOX 프로젝트와 그 설계 데이터 — BOX가 선박 좌표로 보고함을 고정 | 테스트 |

생성은 결정적입니다(같은 입력 → 같은 파일, 격실 UUID는 이름 기반 해시).

## 4. 이중 검토 (도면 ↔ 설계 데이터 ↔ 앱)

| 검토 | 방법 | 결과 |
|---|---|---|
| 도면 = 설계 데이터 | `tools/dxf-check.cjs`가 DXF의 닫힌 외곽선(LINE 도면은 벽 선이 만드는 닫힌 면)과 문자를 읽어(`lib/dxf-in.cjs`) 설계 데이터와 실 번호·이름·면적 대조 | 4 Deck 79/79 일치 (v1에서 L자 선실 번호가 화장실 안에 찍힌 결함을 이 도구로 찾아 고침) |
| BOX 계산 | BOX가 `T3.box.json`을 열고 CAL이 79실 모두 계산 | 미완료 0, 설계 데이터 검사 문제 0 |
| PHG D 실 인식 | 셸에서 `T3_D2.dxf`를 PHG D로 가져와 PHG D 자신의 실 인식으로 3개 지점 확인 | 211 선원침실 01 / 261 화장실 / 202 복도 |
| BOX DXF 가져오기 | 셸에서 `T3_D2.dxf`를 BOX `DXF 열기`로 | 도형·문자 모두 들어옴 |
| PHG D 입력 도면 | HVAC Grid가 PHG D로 보내는 Deck 도면(`deckDxf`)을 다시 읽어 설계 데이터와 대조 | S5 5 Deck, T3 4 Deck 모두 일치 |
| 통합 DXF | 출력한 통합 DXF(R12)를 다시 읽어 실 수 대조 | 모든 실 |
| 외부 DXF 판독기 | `T3_*.dxf`와 PHG D로 보내는 Deck 도면을 ezdxf 1.4(Python)로 읽기 — 2차 리뷰 R2-10에서 하위 클래스 표시 누락으로 거부되던 것을 고침 | 5개 파일 + Deck 도면 모두 읽힘, 한글 실 이름 그대로 |

자동 테스트: `test/project.test.cjs`(도면 대조·생성기·좌표 고정), `test/e2e/t3.e2e.cjs`(앱 전체).
