# 별도 프로그램 "SOLAS 방화 등급 표기" 시험·검토 — 2026-10-21

대상: `dist/SOLAS_방화등급표기.html` (커밋 7d86b6f, `tools/make-solas-tool.cjs` + `tools/solas-tool/app.html`).
방법: 프로그램을 `file://`로 열고(독립망과 같은 조건, 서버 없음) Playwright로 입력 18가지를 넣어 결과를 기록했다. 그 다음 `app.html` 코드를 한 줄씩 검토했다. 시험용 도면은 따로 만들었다: CP949 한글 R12, 폴리라인+MTEXT, 이름에 HTML이 든 도면, 400실, 빈 파일, DXF가 아닌 파일, 글자 없는 도면, 깨진 JSON, 다른 JSON.

## 1. 결론

**계산과 표기는 맞고, 독립망 조건(외부 요청 0, 설치 없음)도 지킨다.** T3를 Deck별 DXF 4개로 열면 HVAC Grid 본 프로그램과 같은 실 수(20·27·22·10)와 같은 등급이 나온다.

다만 **도면을 여는 단계에 결함 4건**이 있었다. 가장 큰 것은 **여러 Deck을 한 DXF에 나란히 그린 도면**이었다. 이런 도면을 Deck 하나로 읽어 Deck 사이 갑판 등급(바닥·천장 A-60 등)이 모두 빠졌는데, 화면에는 경고가 없었다. 실무 일반배치도(GA)가 대개 이 형태라 P1로 보고 고쳤다. 나머지 3건과 사소한 5건도 고쳤다.

## 2. 입력별 시험 (고치기 전)

| 입력 | 결과 | 판정 |

## 3. 코드 검토로 찾은 것

| # | 내용 | 우선 | 조치 |
|---|---|---|---|
| S-01 | 여러 Deck을 나란히 그린 한 DXF를 Deck 하나로 읽음. 갑판 경계가 빠지고 경고도 없음 | P1 | **고침** — 1.5 m 넘게 떨어진 실 묶음(3실 이상)이 2개 이상이면 경고하고 "Deck N개로 나누기" 버튼을 보임. 나누면 왼쪽→오른쪽(세로로 그린 도면은 아래→위)이 아래 Deck부터다. 위 Deck은 **같은 종류의 수직 공간(계단·트렁크·케이싱·승강기)의 중심이 겹치도록** 옮긴다. 공통 수직 공간이 없으면 묶음 왼쪽 아래 모서리로 맞추고 "확인 필요"를 표시한다. Deck마다 이동 X·Y 입력을 추가해 사용자가 고칠 수 있다. 처음 시도한 "묶음 모서리 맞춤"은 T3 항해선교 Deck(다른 Deck보다 8 m 앞에서 시작)을 8 m 어긋나게 놓았다. 그래서 수직 공간 기준으로 바꿨다 |
| S-02 | 빈 파일·DXF가 아닌 파일·실 0개 도면도 Deck으로 추가됨 | P2 | **고침** — Deck으로 넣지 않고 이유를 씀("DXF 파일이 아닙니다", "실을 찾지 못했습니다 (벽 LINE이 닫힌 면이나 닫힌 폴리라인이 필요)") |
| S-03 | 깨진 JSON 오류가 영어 원문이고 파일 이름이 없음. 한 파일이 실패하면 함께 고른 나머지 파일도 열리지 않음 | P2 | **고침** — 파일마다 따로 읽음. 실패한 파일은 이름과 한글 이유를 쓰고, 나머지는 열림 |
| S-04 | 여러 파일을 열면 파일별 결과("실 0개" 경고 등)가 마지막 요약 문구에 덮여 사라짐 | P2 | **고침** — 파일별 결과를 상태 줄에 모두 남김 (오류는 빨강, 경고는 주황) |
| S-05 | 작업 파일을 검증하지 않아 손상된 파일이 상태를 깨뜨릴 수 있음 | P3 | **고침** — Deck·실·도형이 있는지 확인하고, 아니면 "작업 파일이 손상되었습니다" |
| S-06 | Deck을 빼도 그 실의 공간 지정·벽 등급 지정이 남아 작업 파일에 저장됨. 확인 없이 바로 빠짐 | P3 | **고침** — 확인 후 그 Deck 실의 지정을 함께 지움 |
| S-07 | 창 크기를 바꾸는 동안 매번 전체를 다시 그림 (400실이면 한 번에 약 0.7초) | P3 | **고침** — 크기가 멈춘 뒤(0.2초) 폭이 바뀐 경우에만 다시 그림 |
| S-08 | 범례에 방화댐퍼·슬리브·갑판 관통 기호가 나옴. 이 도구는 관통부를 다루지 않음 | P3 | **고침** (`lib/fire-plan.cjs`) — 관통부가 있을 때만 그 기호를 보임. HVAC Grid 본 프로그램은 관통부가 있으면 그대로 보임 |
| S-09 | 두 Deck의 높이 Z가 같아도 아무 표시가 없음 (쌓는 순서가 모호) | P3 | **고침** — Deck 목록에 "높이 Z가 다른 Deck과 같음" 경고 |
| S-10 | JSON을 열면 지금 열린 도면이 확인 없이 바뀜 | P3 | **고침** — 열린 도면이 있으면 확인을 받음 |

알고도 그대로 둔 것:
- **벽 등급 직접 지정은 경계 위치로 기억한다.** 그래서 이동 X·Y를 바꾸면 그 Deck의 지정이 풀린다. 나누기와 이동을 먼저 하고 벽을 지정하는 순서로 안내한다(`docs/SOLAS.md` 6b).
- **벽 선택은 마우스로만 된다.** SVG 선이라 키보드로는 고를 수 없다. 실 분류 표는 키보드로 쓸 수 있다.
- **HVAC Grid 통합 DXF와 방화 등급도 DXF는 입력 도면이 아니다.** 열리기는 하지만 번호·이름 글자가 다르다. 원래 Deck 도면이나 HVAC Grid JSON을 쓰면 된다.

## 4. 고친 뒤 시험

- `test/e2e/solas-tool.e2e.cjs`에 회귀 시험을 추가했다:
  - 빈 DXF·깨진 JSON·실 없는 DXF·정상 DXF를 함께 열면, 정상 1개만 Deck이 되고 상태 줄에 4개 결과가 한글로 남는다.
  - T3_ALL.dxf를 열면 경고가 나오고, 나누면 Deck별 DXF 4개와 **경계 종류별 개수·갑판 등급·표기 수가 모두 같다**(이동 X 0, −25,000, −50,000, −75,000 mm).
  - Deck을 빼면 그 Deck의 지정이 지워진다.
  - 범례에 관통 기호가 없다.
- 이 시험들은 고치기 전 코드에서 실패한다(빈 DXF가 Deck으로 들어가 대기 조건을 못 넘음). 고친 뒤에는 통과한다.
- 전체 시험 `npm run test:all` 통과, `dist/SOLAS_방화등급표기.html`과 독립망 복사본을 다시 만들었다.
